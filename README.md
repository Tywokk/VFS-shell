# VFS Shell Emulator

Эмулятор командной строки UNIX-подобной ОС с графическим интерфейсом
(Python 3, tkinter). Практическая работа, вариант 28.

## Общее описание

Окно с областью вывода и строкой ввода. Ввод делится по пробелам на
команду и аргументы. Приглашение показывает пользователя и текущий каталог
(`user@vfs:/home/user$`). Заголовок окна содержит имя VFS. При запуске в окно
и в консоль выводятся все параметры и сведения о загруженной VFS
(`[debug] ...`). Все операции с VFS выполняются в памяти.

## Параметры командной строки

| Параметр | Описание |
|----------|----------|
| `--vfs PATH` | XML-файл с VFS; без параметра создаётся VFS по умолчанию |
| `--log PATH` | путь к XML-логу вызовов команд (без параметра лог не пишется) |
| `--script PATH` | стартовый скрипт эмулятора |

## Команды

| Команда | Описание |
|---------|----------|
| `ls [-a] [-l] [путь...]` | содержимое каталога или файл |
| `cd [путь]` | сменить каталог; без пути - перейти в корень `/` |
| `tail [-n N] файл...` | последние N строк файла (по умолчанию 10) |
| `whoami` | имя пользователя (`user`) |
| `chmod режим путь...` | изменить права доступа, только в памяти |
| `tree` | служебная команда: показывает содержимое VFS |
| `exit` | закрывает эмулятор |

Пути бывают абсолютными (`/home/user`) и относительными (`docs`,
`../etc`); поддерживаются `.` и `..`, выше корня подняться нельзя.

* `ls`: `-a` показывает скрытые файлы (имена с точки), `.` и `..`;
  `-l` показывает тип (`d` каталог, `-` файл), права (`rwxr-xr-x`),
  размер в байтах и имя;
  ключи можно писать слитно (`-la`). Для нескольких путей перед
  содержимым печатается заголовок `путь:`, как в UNIX.
* `tail`: для нескольких файлов перед каждым печатается `==> файл <==`.
  Двоичные файлы (например, из base64) не выводятся, это ошибка.
* `chmod`: режим задаётся числом из 1-3 восьмеричных цифр (`755`) или
  символьной записью: кому (`u`, `g`, `o`, `a`), действие (`+`, `-`, `=`),
  права (`r`, `w`, `x`), например `u+x`, `go-w`, `a=r`, `+x` (без «кому» -
  всем). Права хранятся только в памяти, XML-файл VFS не изменяется. По
  умолчанию у файлов `rw-r--r--`, у каталогов `rwxr-xr-x`. Права меняются
  и показываются в `ls -l`, доступ по ним не ограничивается.

Ошибки (неизвестная команда или опция, нет файла или каталога, лишние
аргументы и т.д.) выводятся красным, например:
`cd: x: нет такого файла или каталога`.

## VFS

Источник VFS — XML-файл. Корневой элемент `<vfs>` — корневой каталог.
Внутри `<dir name="...">` (каталог) и `<file name="...">` (файл). Текст
файла пишется как есть; двоичные данные пишутся в base64 с атрибутом
`encoding="base64"`.

```xml
<vfs>
  <dir name="home">
    <file name="notes.txt">Текст</file>
    <file name="data.bin" encoding="base64">AAECA/8=</file>
  </dir>
</vfs>
```

VFS читается в память целиком, на диск ничего не распаковывается и файл
не изменяется. Если `--vfs` не задан, в памяти создаётся VFS по
умолчанию. При ошибке в файле (нет файла, неверный XML, повторяющиеся
имена, неверный base64) эмулятор печатает `Ошибка VFS: ...` и не
запускается. Примеры лежат в папке `vfs/`: `minimal.xml`,
`several_files.xml`, `deep.xml` (пять уровней), `demo.xml` (для скрипта
этапа 4: многострочные файлы, скрытый файл, пустой каталог, base64), а
также `broken.xml` для проверки ошибок.

## Лог (XML)

Файл обновляется после каждой команды:

```xml
<events>
  <event>
    <time>2026-10-07T12:00:01</time>
    <command>foo</command>
    <arguments><arg>bar</arg></arguments>
    <error>foo: команда не найдена</error>
  </event>
</events>
```

## Стартовый скрипт

Одна команда на строку; пустые строки и строки с `#` пропускаются.
В окне отображаются и ввод, и вывод. Выполнение останавливается на первой
ошибке с сообщением `Скрипт остановлен: ошибка в строке N`.

| Скрипт | Что показывает |
|--------|----------------|
| `startup_ok.emu` | команды без ошибок для любой VFS, завершение `exit` |
| `startup_error.emu` | остановка на неизвестной команде |
| `startup_all.emu` | все команды (`deep.xml`), в конце ошибка `tree extra` |
| `startup_stage4.emu` | все режимы `ls`, `cd`, `tail`, `whoami` (`demo.xml`), в конце ошибка |
| `startup_stage5.emu` | все режимы `chmod` (`demo.xml`), в конце ошибка |

Скрипт останавливается на первой ошибке, поэтому в каждом скрипте она одна,
в конце. Остальные ошибки можно проверить вручную: `ls -x`, `ls nope`,
`cd readme.txt`, `cd a b`, `tail`, `tail -n abc f`, `tail /data.bin`,
`whoami x`, `chmod`, `chmod 755`, `chmod 999 f`, `chmod u+q f`,
`chmod 755 nope`.

## Скрипты ОС

Скрипты в `scripts/` запускают эмулятор и проверяют результат (общие
функции в `lib.sh`).

| Скрипт | Что проверяет |
|--------|---------------|
| `test_params_basic.sh` | каждый параметр отдельно и все три вместе |
| `test_params_log.sh` | содержимое XML-лога, остановка на ошибке |
| `test_params_errors.sh` | неизвестные параметры, параметры без значения |
| `test_vfs_variants.sh` | VFS по умолчанию, минимальная, несколько файлов (с base64), глубокая |
| `test_vfs_errors.sh` | ошибки VFS: нет файла, битый XML |

Скрипты написаны для sh (Linux, macOS; в Windows через Git Bash или WSL).

## Сборка и тесты

```
make run ARGS="--vfs vfs/deep.xml --script scripts/startup_all.emu"
make test      # unit-тесты
make test-os   # скрипты ОС
make lint      # flake8, длина строки 80
```

Требуется Python 3.9+ с tkinter (Debian: `apt install python3-tk`).
Без дисплея: `RUNNER="xvfb-run -a" make test-os`.
В Windows вместо `make`: `python -m src.main ...` и
`python -m unittest discover -s tests -t .`.
