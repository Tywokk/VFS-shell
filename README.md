# VFS Shell Emulator

Эмулятор командной строки UNIX-подобной ОС с графическим интерфейсом
(Python 3, tkinter). Практическая работа, вариант 28.

## Общее описание

Окно с областью вывода и строкой ввода. Ввод делится по пробелам на
команду и аргументы. Заголовок окна содержит имя VFS. При запуске в окно
и в консоль выводятся все параметры и сведения о загруженной VFS
(`[debug] ...`). Все операции с VFS выполняются в памяти.

## Параметры командной строки

| Параметр | Описание |
|----------|----------|
| `--vfs PATH` | XML-файл с VFS; без параметра создаётся VFS по умолчанию |
| `--log PATH` | путь к XML-логу вызовов команд (без параметра лог не пишется) |
| `--script PATH` | стартовый скрипт эмулятора |

## Команды

| Команда | Описание |
|---------|----------|
| `ls [args]` | заглушка: печатает имя и аргументы |
| `cd [args]` | заглушка: печатает имя и аргументы |
| `tree` | служебная команда: показывает содержимое VFS |
| `exit` | закрывает эмулятор |

Ошибки (неизвестная команда, аргументы у `exit` и `tree`) выводятся
красным.

## VFS

Источник VFS — XML-файл. Корневой элемент `<vfs>` — корневой каталог.
Внутри `<dir name="...">` (каталог) и `<file name="...">` (файл). Текст
файла пишется как есть; двоичные данные пишутся в base64 с атрибутом
`encoding="base64"`.

```xml
<vfs>
  <dir name="home">
    <file name="notes.txt">Текст</file>
    <file name="data.bin" encoding="base64">AAECA/8=</file>
  </dir>
</vfs>
```

VFS читается в память целиком, на диск ничего не распаковывается и файл
не изменяется. Если `--vfs` не задан, в памяти создаётся VFS по
умолчанию. При ошибке в файле (нет файла, неверный XML, повторяющиеся
имена, неверный base64) эмулятор печатает `Ошибка VFS: ...` и не
запускается. Примеры лежат в папке `vfs/`: `minimal.xml`,
`several_files.xml`, `deep.xml` (пять уровней), а также `broken.xml` для
проверки ошибок.

## Лог (XML)

Файл обновляется после каждой команды:

```xml
<events>
  <event>
    <time>2026-10-07T12:00:01</time>
    <command>foo</command>
    <arguments><arg>bar</arg></arguments>
    <error>foo: команда не найдена</error>
  </event>
</events>
```

## Стартовый скрипт

Одна команда на строку; пустые строки и строки с `#` пропускаются.
В окне отображаются и ввод, и вывод. Выполнение останавливается на первой
ошибке с сообщением `Скрипт остановлен: ошибка в строке N`.

| Скрипт | Что показывает |
|--------|----------------|
| `startup_ok.emu` | команды без ошибок, `tree`, завершение `exit` |
| `startup_error.emu` | остановка на неизвестной команде |
| `startup_all.emu` | все команды и режимы, в конце ошибка `tree extra` |

## Скрипты ОС

Скрипты в `scripts/` запускают эмулятор и проверяют результат (общие
функции в `lib.sh`).

| Скрипт | Что проверяет |
|--------|---------------|
| `test_params_basic.sh` | каждый параметр отдельно и все три вместе |
| `test_params_log.sh` | содержимое XML-лога, остановка на ошибке |
| `test_params_errors.sh` | неизвестные параметры, параметры без значения |
| `test_vfs_variants.sh` | VFS по умолчанию, минимальная, несколько файлов (с base64), глубокая |
| `test_vfs_errors.sh` | ошибки VFS: нет файла, битый XML |

Скрипты написаны для sh (Linux, macOS; в Windows через Git Bash или WSL).

## Сборка и тесты

```
make run ARGS="--vfs vfs/deep.xml --script scripts/startup_all.emu"
make test      # unit-тесты
make test-os   # скрипты ОС
make lint      # flake8, длина строки 80
```

Требуется Python 3.9+ с tkinter (Debian: `apt install python3-tk`).
Без дисплея: `RUNNER="xvfb-run -a" make test-os`.
В Windows вместо `make`: `python -m src.main ...` и
`python -m unittest discover -s tests -t .`.

## Примеры

```
user@vfs:~$ tree
/
hello.txt
home/
  readme.txt
user@vfs:~$ ls -l /home
ls: заглушка, аргументы: -l /home
user@vfs:~$ tree x
tree: слишком много аргументов
user@vfs:~$ foo
foo: команда не найдена
```
